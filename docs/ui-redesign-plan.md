# UI 全面再設計プラン — 検索ファーストの「リボン大図鑑＋プランナー」

作成: 2026-07-29 ／ 状態: 承認済み・実装中

## 背景・課題

- 旧設計は「マイポケモン登録 → 個体のリボンをチェック」という**記録アプリの導線**が主役で、
  「調べる」機能（逆引き・合計数・ソフト別解禁リボン）がガイドの末端に埋まっていた
- ユーザーの目的は**攻略の事前調査と計画**（ribbons.guide のようなコレクション台帳とは別アプローチ）:
  - このポケモンはトータル何個のリボン/あかしをつけられる？
  - 第◯世代にいるこのポケモンはどのリボンをつけられる？
  - このリボンはどのポケモンにつけられる？
  - このソフトを買うと何のリボンが解禁される？（中古屋モード）

## 設計原則

1. **検索が主役**: ホーム = 統合検索（ポケモン名／リボン名／ソフト名を1箱で）
2. **登録不要**: すべての参照機能はマイポケモン登録なしで使える
3. **相互リンク**: ポケモン⇄リボン⇄ソフトのエンティティページを網の目に繋ぐ
4. **所持設定はグローバル文脈**: 所持ハード/ソフト設定が全画面の表示に効く
   （取れる=緑 / ソフト買えば取れる=琥珀 / 不可=灰）
5. **記録は脇役**: 個体チェック機能は残すが導線の主役にしない

## 継承するもの（作り直さない）

- データ層: pokemon-data 正本 + 生成スクリプト（games/pokemon/ribbons/marks）+ 突合テスト
- 判定エンジン: ribbonEligibility / ribbonIndex（種族×リボン適格性・逆引き）
- 転送ルート・シャドウデータ、ストアの永続化キー（localStorage 互換維持）
- 技術スタック: SvelteKit 2 + Svelte 5 Runes + Tailwind v4 + adapter-static(SSG) + PWA

## 新しい情報設計（ルーティング）

SSG を軽く保つため動的 [id] ルートは使わず、クエリパラメータ方式（共有可能URL・オフライン完全対応）。

| ルート | 役割 |
|---|---|
| `/` | 統合検索ホーム。検索1箱 + 世代タイル + カテゴリタイル + 中古屋モード導線 |
| `/pokemon?p=<id>` | ポケモン詳細: 取得可能リボン/あかし合計、世代別内訳、条件注記、所持ソフト考慮トグル |
| `/ribbon?r=<id>` | リボン詳細: 公式名(日英)・条件・対象ソフト・カテゴリ・HOME転送可否・つけられるポケモン逆引き |
| `/game?g=<id>` | ソフト詳細（中古屋モード）: このソフトで取れるリボン一覧、所持状況との差分（=買うと何が増えるか） |
| `/plan` | プランナー: 旧ロードマップ + urgent/missed 判定 + 転送ルートを統合 |
| `/box` | 記録（旧トラッカー+クイックの縮小版）: マイポケモンのチェックリスト |
| `/settings` | 所持ハード/ソフト設定（旧セットアップ）+ データのエクスポート/インポート（新規） |

旧ルート（/quick /roadmap /setup /guide）は対応する新ルートへリダイレクト or 撤去。

## 実装フェーズ

- **R1: 調べる系のコア** — 統合検索ホーム + ポケモン詳細 + リボン詳細（ribbonIndex 活用）
- **R2: 中古屋モード** — ソフト詳細 + 所持設定のグローバル文脈化（3色表示）
- **R3: 計画と記録** — /plan 統合、/box への記録機能移設、旧画面の撤去・リダイレクト
- **R4: 仕上げ** — バックアップ（エクスポート/インポート）、PWA磨き、旧 docs 更新

各フェーズごとに lint / check / test / build を通してからコミットする。

## 非目標

- Ribbons.Guide（GPL-3.0）のコード・データ・デザインの流用はしない（アプローチも別物）
- 個体単位の詳細記録（性格・ボール等のコレクション管理）は対象外
- species×game の厳密な出現可否データ（地方図鑑・入国制限）は将来課題
  （当面は「初登場世代 ≤ リボン世代」近似 + 免責注記。pokemon-data 側の拡張ネタ）
